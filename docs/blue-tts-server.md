# BlueTTS server voice (iOS)

PocketPal's **BlueTTS server** voice is optional and **online**. In Voice & Speech, enter and save the base URL of a server running [BlueTTS's OpenAI-compatible server](https://github.com/maxmelichov/BlueTTS#openai-compatible-server), e.g. `https://speech.example.com` or `http://192.168.1.20:8000` on a trusted LAN. Do not append `/v1/audio/speech`. Select any of the 15 listed BlueV3 voices; preview, message replay, auto-speak, and voice-mode completion all use the same TTS store. It sends the response text to the configured server. It is not offline; never put a token or password into the URL. Servers requiring API keys are unsupported (no authentication header is sent). For remote access use TLS and a trusted/private deployment.

The native iOS bridge POSTs `{"model":"bluev3","input":"…","voice":"noa","response_format":"wav"}` to `/v1/audio/speech` and plays returned WAV through `AVAudioPlayer`. It handles HTTP/network failures, malformed/oversized audio, cancellation and playback errors. The URL is persisted locally as a non-secret preference; audio is not written to disk. The voice is not shown on Android. Streaming responses are buffered until completion before the request, rather than synthesized sentence by sentence; long responses can take longer and output over 25 MB is rejected. Errors appear in the Voice & Speech BlueTTS panel. The existing 4 GiB TTS availability gate still applies unless explicitly overridden by the user.

**Not an on-device BlueTTS port:** upstream BlueV3 uses several ONNX graphs and language-specific frontends; English/German/Spanish/Italian/Russian G2P depends on the Linux x86-64 glibc `polyg2p` wheel, Hebrew requires bundled Renikud, and Yiddish has a separate frontend. An iOS-compatible G2P build, graph packaging, and native inference integration have not been implemented or validated. No offline BlueTTS option is displayed.
